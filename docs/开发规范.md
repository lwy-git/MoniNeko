# UniApp Vue3 项目\+组件完整开发规范（Markdown版）

# 一、整体技术基础规范

1. 统一使用 **Vue3 \+ script setup** 语法，禁用选项式API

2. 构建工具统一 Vite，样式统一 SCSS，启用 uni\.scss 全局变量

3. 代码格式化：2空格缩进、UTF\-8编码、LF换行、ESLint\+Prettier校验

4. 全局禁止使用原生DOM/BOM，跨端优先使用uni官方API

# 二、项目目录规范

```plain text
src
├── api         接口请求（按业务模块拆分）
├── components  全局公共组件
├── pages       路由页面
├── hooks       全局通用组合逻辑
├── store       Pinia状态管理
├── utils       工具函数
├── config      环境配置、常量
├── static      静态资源
├── styles      全局公共样式
```

- 页面私有组件：放入**当前页面同级components**，不丢全局组件库

- 静态资源仅存放static，禁止随意引用本地图片路径

# 三、全局命名规范

1. 文件/页面/组件：**短横线命名 kebab\-case**（例：user\-login\.vue、custom\-button\.vue）

2. JS工具函数、变量：**小驼峰**（例：getUserInfo、formData）

3. 常量：**全大写\+下划线**（例：MAX\_COUNT、BASE\_URL）

4. 自定义事件：短横线命名（例：@confirm\-submit、@item\-click）

5. CSS类名：短横线命名，禁止ID选择器（例：\.user\-info、\.btn\-primary）

# 四、Vue3 script setup 强制写法

1. 组件结构固定三段式：template \+ script setup \+ scoped样式

2. 传参必须用`defineProps`，必填/类型/默认值齐全，数组对象用工厂函数（例：default: \(\) =\&gt; \[\]）

3. 子传父事件统一用`defineEmits`声明（例：const emit = defineEmits\(\[\&\#39;confirm\&\#39;, \&\#39;cancel\&\#39;\]\)）

4. 元素/组件ref统一后缀`xxxRef`（例：modalRef、listRef）

5. 禁止直接修改props数据，全部通过emit向上通知

6. 生命周期直接引入使用，不写this（例：onLoad、onUnmounted）

# 五、Template模板规范

1. 指令顺序：v\-for \&gt; v\-if \&gt; class \&gt; 属性 \&gt; 事件

2. v\-for必须绑定唯一key，禁止v\-for与v\-if同级使用

3. 统一使用简写：:属性（v\-bind）、@事件（v\-on）

4. 属性超过3个分行编写，保持整洁

5. 图片统一用`\&lt;image\&gt;`标签，开启懒加载（lazy\-load=\&\#34;true\&\#34;）

# 六、样式开发规范

1. 组件/页面样式必须加 **scoped**（避免样式污染）

2. 移动端尺寸优先使用 **rpx** 适配全端

3. 严禁行内大量样式，样式统一抽离到\&lt;style\&gt;中

4. 全局通用样式抽入styles文件夹，组件私有样式隔离

5. 统一使用项目预设主题色，不随意写固定色值

# 七、多端适配规范

1. 平台差异使用**清晰注释条件编译**（例：// \#ifdef H5 \.\.\. // \#endif）

2. H5、小程序、App差异化逻辑单独隔离，不混写

3. 路由跳转统一使用uni路由API（uni\.navigateTo、uni\.redirectTo等），禁止原生跳转

# 八、性能优化规范

1. 频繁切换显隐用v\-show，一次性条件渲染用v\-if

2. 长列表必用虚拟列表（如uv\-list），避免一次性渲染大量数据

3. 页面销毁onUnload清除定时器、事件监听、未完成请求

4. 精简响应式变量，非动态数据不使用ref/reactive

# 九、复杂组件拆分核心规范（重点）

## 9\.1 拆分原则

- **SFC视图层\(\.vue\)：**只负责渲染结构、样式、事件触发（不写复杂逻辑）

- **Hooks逻辑层\(useXXX\.js\)：**只负责数据、请求、业务逻辑（不写视图相关）

- 组件代码超300行**必须强制拆分**

## 9\.2 组件目录拆分结构

```plain text
业务组件文件夹
├─ index.vue  主视图入口（极简干净）
└─ hooks
   ├─ useList.js    列表逻辑（请求、数据处理）
   ├─ useForm.js    表单逻辑（校验、提交）
   ├─ useModal.js   弹窗逻辑（显隐、数据）
   └─ index.js      统一导出hooks（方便引入）
```

## 9\.3 Hooks编写规范

1. 命名统一`use\+业务名`（例：useForm、useSearch、useOrder）

2. 单一职责：一个hooks只处理一类业务（不写大杂烩逻辑）

3. 内部私有变量不对外暴露，只导出页面需要的变量与方法

4. hooks内只处理数据逻辑，**不写弹窗、吐司、路由跳转**（交互提示放SFC）

5. 网络请求统一封装进hooks，视图层只调用方法（不写请求逻辑）

## 9\.4 视图层SFC规范

1. 只引入hooks并解构数据与方法（不写复杂逻辑）

2. template只做页面结构渲染，简洁清晰

3. 点击事件仅做方法调用，不写复杂业务代码

4. 视图交互提示（Toast、弹窗、路由跳转）统一写在\.vue内

## 9\.5 禁止行为

- ❌ 禁止\.vue页面堆积大量请求、判断、业务逻辑

- ❌ 禁止hooks内部操作DOM、编写页面交互

- ❌ 禁止一个hooks包揽所有业务逻辑

# 十、接口与请求规范

1. 统一封装全局request请求拦截、响应拦截（处理token、错误提示）

2. 接口按模块拆分api文件（例：api/user\.js、api/order\.js），页面不直接写请求地址

3. 统一处理loading、错误提示、请求失败回调（避免重复代码）

# 十一、Git提交规范

## 提交类型

- feat：新增功能（例：feat: 添加用户登录组件）

- fix：修复bug（例：fix: 修复列表加载失败bug）

- style：代码格式调整（不改变逻辑）

- refactor：代码重构（不新增功能、不修复bug）

- docs：文档/注释修改

- chore：依赖/配置修改

## 提交格式

`类型: 简要描述`（例：feat: 新增用户登录组件）

# 十二、团队统一强制约束

1. 所有新页面、新组件**默认走Hooks\+SFC拆分模式**

2. 老复杂组件逐步重构拆分，禁止继续堆积代码

3. 组件必须写基础注释：用途、入参、触发事件

4. 所有页面统一规范生命周期调用逻辑（例：请求放onLoad）

5. 状态管理轻量化，简单数据用hooks，全局共享数据用Pinia
